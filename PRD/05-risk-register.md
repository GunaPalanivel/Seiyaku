# Product risks and closure requirements

Owners are roles for the team to assign; no people are automatically assigned.
The table defines closure evidence, not a history of completed work.

| ID | Priority | Risk | Owner role | Closure requirement |
|---|---|---|---|---|
| R01 | P0 | Wrong stage, schema or objective contract | Contract owner | Actual current statements/API payload and every required constraint mapped |
| R02 | P0 | Candidate changes the problem or trusted evaluator files | Evaluation owner | Read-only isolation and before/after identity; tampering controls rejected |
| R03 | P0 | False objective or conflicting fields inflate fitness | Validator owner | Independent objective recomputation and representation agreement for every family |
| R04 | P0 | Missing/faulted cases or stale reports distort comparisons | Evaluation owner | Complete attempt-bound ledger; infrastructure errors invalidate comparison |
| R05 | P0 | Mandatory-service construction fails despite feasible input | Domain owner | Checked complete public witnesses and bounded repair/direct-feasibility controls |
| R06 | P0 | Provider reads holdouts or loses auth across platform bridge | Provider/custodian | Separate inaccessible holdouts, bounded bridge tests and existing-entitlement proof |
| R07 | P0 | Failed trial or interrupted save replaces the incumbent | Release owner | Immutable sources, committed selection, journal recovery and mismatch refusal |
| R08 | P0 | Actual runtime/scale differs from development assumptions | Runtime owner | Chosen organizer image, full process limits and scale-diverse legal cases |
| R09 | P0 | Final protocol or scoring edge is unpublished/ambiguous | Final owner | Authoritative current rule snapshot; unresolved decision-critical fields block release |
| R10 | P1 | Dense construction, overhead or shutdown consumes budget | Domain/runtime owner | Sparse representations and measured full-lifetime resource checks |
| R11 | P1 | Added libraries or orchestration do not improve performance | Experiment owner | Matched end-of-budget comparison; retain simpler control if gain is inconclusive |
| R12 | P1 | Known-family performance does not transfer | Framework owner | Fresh held-out families, fixed allowances and complete intervention accounting |
| R13 | P1 | Imported source/data lacks redistribution rights | Release owner | Exact provenance/license review before import or publication |
| R14 | P1 | Model quota cannot sustain requested workload | Provider owner | Request counters, bounded stop/replay; no paid or alternate-account workaround |
| R15 | P0 | Public Git includes internal research or local secrets | Maintainer | Stage only agreed product docs/templates/skeleton; inspect complete publication diff |

If a risk becomes decisive, inspect the actual source, runtime and legal inputs.
Record uncertainty instead of selecting convenient semantics. Ask for genuinely
missing access or decisions; external messages and submissions remain authorized
separately.
